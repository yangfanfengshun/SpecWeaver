# SpecWeaver v0.7.0

v0.7.0 聚焦安装、配置和 Tower 认证体验，不包含 v0.7.1 规划中的蓝湖设计理解新工具。

## 安装流程

- 安装和认证配置完全分离；安装结束后提示用户主动运行
  `specweaver configure`。
- 默认处理 Codex、Claude Code 和 Cursor；缺少某个宿主 CLI 时只跳过该宿主，
  不阻断公共 runtime、终端命令和其他宿主。
- Cursor 优先识别 `agent`，兼容 `cursor-agent`，只提供 `/plugin` 或 IDE
  `/add-plugin` 原生安装指引，不执行不存在的插件子命令。
- Claude 继续通过插件清单加载 MCP，并提示 `/reload-plugins` 和 `/mcp`，无需手工
  修改 `settings.json`。

## 配置流程

- `specweaver configure` 先展示 Tower、Eolink、蓝湖的多选菜单。
- 直接执行 `specweaver configure <platform>` 时立即进入指定平台。
- 蓝湖支持启用或更新、停用、返回；未选择平台不会改变原配置。
- Eolink 和蓝湖继续保存后延迟验证。

## Tower 认证

- 普通配置使用邮箱和不回显的密码执行一次真实网页登录，成功后原子保存邮箱、
  密码和生成的 Cookie。
- 登录失败不覆盖旧配置，也不会自动重复提交密码。
- 保留 `specweaver configure tower --cookie` 人工恢复入口。
- MCP 请求发现 Cookie 过期后，使用邮箱密码自动续期一次，原子更新 Cookie，并
  重试原始请求；并发请求共享同一次登录。
- 密码错误、验证码、二次验证、网络异常和网页登录兼容问题分别停止并给出恢复
  指引，认证值不会写入日志或错误信息。

## 验证

- 自动化测试覆盖平台多选、Tower 登录分类、Cookie 兜底、并发单次续期、缺失宿主
  CLI、Cursor 命令识别和原有 MCP 基线。
- 已使用用户本机凭据完成正确账号密码真实登录与新 Cookie 独立连接检查；凭据未
  进入对话、测试数据或仓库。
