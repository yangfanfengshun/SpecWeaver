# SpecWeaver v0.8.1

v0.8.1 重点修复 v0.8.0 流程拆分后的两个实际体验问题：Tower 图片现在会在读取任务时统一下载到用户缓存，快速分析、Bug 分析和完整收集都能直接看到图片；完整资料收集成功后也会直接进入需求分析，不再额外等待一次确认。

## 本次更新

- Tower 读取任务时会同步下载正文与评论中的图片，包括 Tower 以无扩展名附件形式展示
  的截图，保存到 `~/.specweaver/cache/tower/<任务ID>/images/`，并在缓存元数据中记录
  本地路径、下载统计和失败原因。
- 快速分析、Bug 分析与完整收集统一消费 Tower 图片缓存，不再因选择不同流程而缺失图片证据。
- 完整收集状态为 `success` 时自动调用需求分析；用户明确要求只收集时仍会在收集完成后停止，状态为 `partial` 时则保留补充资料的确认边界。
- 新增完整收集决策表和机器可校验的工作流语义清单，防止 Skill、提示词和 MCP 返回语义发生漂移。
- 新增提交与 Pull Request 验证工作流，并在公开发布前执行完整测试与版本清单检查。
- 更新项目复核、Cursor 安装更新、GitLab 自动化及 MCP 数据源接入等调研文档。

## 验证结果

- 通过 Tower 图片发现、无扩展名附件识别、下载、重复缓存、失败记录与工具轻量返回测试。
- 通过快速分析、完整收集自动分析、只收集停止和部分成功暂停等流程语义测试。
- 通过 GitHub Actions 配置、插件清单、版本一致性与发布清单检查。
- 通过 142 项全量回归测试。
