# SpecWeaver v0.7.1

v0.7.1 新增蓝湖设计理解能力，让 Agent 读取真实设计结构，而不是只看预览图猜页面。

## 蓝湖设计上下文

- 新增 `lanhu_get_design_detail`，通过现有蓝湖 Cookie 读取真实 Sketch JSON，
  输出技术栈中立的规范化图层树。
- 图层上下文包含层级、坐标、尺寸、显隐、层叠、裁剪、文本、主要样式和资产引用。
- 蓝湖原始事实使用 `source: fact`，由图层关系推导的布局方向使用
  `source: derived`，避免把推断冒充设计标注。
- 自动识别蓝湖 `info` 中的画板根节点，避免扁平节点与嵌套节点重复输出。
- 大型设计稿支持将完整 JSON 写入本地文件，MCP 结果只返回摘要和精简节点导航。

## 蓝湖切图

- 新增 `lanhu_download_slices`，读取设计稿真实切图字段并按 `icon`、`img`、`bg`
  分类保存。
- 按内容 SHA-256 去重，支持部分成功，并保留设计稿、图层、远程地址、本地文件和
  哈希映射。
- 支持把下载结果回写到对应规范化 JSON；预览图和切图使用不同目录，不会互相覆盖。
- 所有结构和资源请求继续只使用 `LANHU_COOKIE`，不新增 Authorization 配置，也不
  引入 Playwright 或 Puppeteer。

## 完整资料收集

- 完整模式在用户确认设计范围后，按稳定编号生成
  `design/lanhu-NNN.json`、`images/lanhu-NNN-preview.*` 和
  `images/lanhu-slices/lanhu-NNN/`。
- `requirement.md` 只记录设计结论和证据链接，不嵌入完整图层树或切图清单。
- 新增轻量 `design-context.json`，把 Tower 任务映射到设计 ID、来源、预览图、结构
  文件、画布和切图目录。

## 可组合 Skill

- 新增 `requirement-collection` 总控 Skill，统一负责模式选择、范围确认、文档写入
  和最终验证。
- Tower、蓝湖和 Eolink 分别由 `tower-source-collection`、
  `lanhu-source-collection`、`eolink-source-collection` 返回统一来源结果；以后可按
  相同协议增加平台，而不把平台细节继续堆进总控。
- `tower-requirement-collection` 保留为旧名称兼容入口，不再维护第二套流程。

## 设计实现闭环

- 新增 `lanhu-design-implementation`，开发 Tower 或本地需求资料时自动发现
  `design-context.json`，先查看预览图，再按需查询结构化事实。
- 提供本地 `query_design.py`，支持摘要、文本/名称、节点、坐标、区域和节点间距查询；
  精确值查询不需要把整份大型 JSON 放入对话。
- 页面实现后要求将实现截图与设计预览对比，并对差异区域再次查询；无法截图时不会把
  普通代码检查误报为视觉还原验证。

## 验证

- 自动化测试覆盖链接解析、图层规范化、重复节点过滤、切图来源映射、敏感字段隔离、
  五个蓝湖 MCP 工具注册、Skill 拆分协议和设计局部查询。
- 已使用真实蓝湖设计验证纯 Cookie 详情读取、61 个节点规范化、2 个切图下载和
  manifest 回写；认证信息未进入产物或日志。
